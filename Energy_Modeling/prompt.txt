Task 4: capacity dilation and differential DRAM weight refetch.

Read Energy_Modeling/CLAUDE.md, FINDINGS.md sections 7.4-7.6 and section 9
item 0, and eccenergy/recon.py first. Task 3 (reconstruction-boundary
placement) is done and is a FIXED-MAPPING study: RECON_OPTIMIZER=False pins
one mapping on every ECC arm, so both arms refetch identically by
construction. I want Task 4, and this is the mechanism.

CAPACITY DILATION. Under the reconstruction arm the on-chip weight
representation is K/N = 39/63 = 0.619 of full width, so the same physical
buffer holds N/K = 1.615x more weights. Effective on-chip weight capacity:
eyeriss_like 75,264 -> 121,580 weights; simple_weight_stationary
164,096 -> 265,078.

DIFFERENTIAL REFETCH. A larger effective tile means the reconstruction arm
reloads weight tiles from DRAM fewer times than the embedded-ECC reference.
A read it never issues removes the DRAM ARRAY energy as well as the
interface energy, so its saving efficiency is 1.0 per uJ, against the
f_if x (1 - K/N) = 0.152 that a fixed mapping buys. This is why Task 3
structurally cannot show it.

Therefore smaller SRAM and reconstruction-aware mapping are MULTIPLICATIVE,
not independent: refetch is what creates the differential. Under a fixed
mapping, shrinking buffers is flat to slightly negative. First-order model,
assuming excess refetch scales inversely with capacity so
R_recon - 1 = (R_emb - 1) x K/N, for R4b vs embedded:

  embedded refetch    eyeriss_like        simple_weight_stationary
  today (1.28/1.07)   11.38% -> 13.32%    5.42% -> 5.68%
  2.0                        -> 17.85%           -> 9.75%
  4.0                        -> 25.77%           -> 16.20%

Section 7.6's 15.2% asymptote does not bind here; this tends toward 47.5%
because the array share is avoided rather than merely narrowed.

Do this in order:
1. Validate the assumption first, no new modelling code. Map each design
   twice, once at declared weight capacity and once at capacity x N/K, and
   diff the per-layer DRAM weight reads. Real tiles are integers, so 1.615x
   capacity may buy a whole extra tile on some layers and nothing on others,
   and the whole table scales with that one number.
2. Then implement Task 4, keeping RECON_OPTIMIZER=True's refusal so
   fixed-mapping numbers can never appear under a heading claiming the
   mapping was optimised.
3. Respect G_rec: a PE-local boundary needs ceil(N/weight_bits)+1 = 9
   co-resident weights, and eyeriss_like's binding layer holds 20 today, so
   a shrink can re-break R4a and R4b. Report infeasible with layers named.
4. Quote the mapper-objective pair: ECC_OPT_METRIC=energy vs edp changes
   eyeriss_like's total energy by 42.6% and decides whether R4b exists.
